## Outcome

Shipped in `../ui` at commit 1cf88ed on `main` over `540e9c3`, by pathspec (`src/components/nav/NavHeader.tsx`, `src/components/nav/NavMobileMenu.tsx`, `CHANGELOG.md`, `package.json`, `pnpm-lock.yaml`), not pushed: the two files re-ported from `packages/ui-nav/src/components/{NavHeader,NavMobileMenu}.tsx` at `fce357d` onto the framework context of plan 1c74a465996d. The panel is a fixed full-width layer under the sticky header offset by `useTopNavHeight`, no portal, no backdrop, no second close button, the list padded `4` and the action row below it; the toggle is `title="Toggle menu"` with `aria-expanded` and `aria-controls` naming the panel's id from `useId` (Chakra v3's `useDisclosure` has no `getButtonProps` or `getDisclosureProps`, so the wiring is written out); the panel is a `toolbar` region. `NavMobileMenuProps` is legacy's shape (`show`, `id`, `onHideMobileMenu` over `NavHeaderProps`; `id` where v2 passed `disclosureProps: any`), recorded under Breaking in the CHANGELOG with the re-port under Fixed. No story renders `NavHeader`, so none changed. The package version stays; the publish is the operator's.

Two choices the plan left open, both made here. Focus: `react-focus-on@3.10.2` (MIT, the legacy dependency at `^3.7.0`, resolved to 3.9.3 in the legacy lockfile; peer `react ^19`; its `returnFocus`, `scrollLock` and isolation defaults unchanged) over Ark's `FocusTrap` from `@chakra-ui/react`, since it is legacy's mechanism whole (focus held, Escape through `onEscapeKey`, `onActivation` for legacy's `handleActivation`, body scroll lock, `aria-hidden` and `pointer-events: none` on the rest of the page), where Ark's trap exposes no Escape (zag's `escapeDeactivates` defaults false and Ark does not pick it), no scroll lock and no outside `aria-hidden`, each to be written by hand. Slide: the plan named Chakra v3's `Presence` against `motion`, and `motion` won, on two pieces of evidence. First, `Presence` was built and a Playwright probe against `pnpm dev` showed it clearing its `hidden` attribute after react-focus-on's activation had run (zag's presence `watch` sends `MOUNT` from a passive effect through `queueMicrotask` and `flushSync`, while react-focus-lock calls `onActivation` synchronously in its client side effect), so legacy's `handleActivation` found a hidden panel and focus never reached it; a plain `Box` hidden in the same render fixed that but played a CSS keyframe (`slide-from-left-full`, `slower`, `ease-out`) where legacy entered on a spring, a change of the visible curve that rule 4 does not cover, which the Parity and Spec reviews both named. Second, decision `ee86d68a` names `motion` as framer-motion's translation, and v2's `Slide` (`@chakra-ui/transition` 2.1.0, `slide.mjs` and `transition-utils.mjs`, read from a local copy) is framer-motion code: `slideLeft` at `left: 0, top: 0, bottom: 0, width: 100%`, enter `x: 0` on `spring` damping 25 stiffness 180, exit `x: -100%` over 0.15s on `[0.4, 0, 0.2, 1]`, `initial="exit"`, always mounted without `unmountOnExit`. The panel is that, verbatim, as a `motion.div` with the inner `Flex` carrying `id`, `hidden` and `display` as legacy's disclosure props left them; `motion@^12.38.0` joins the package's dependencies, the range this site already pins (12.x), so the site holds one copy. The exit slides an empty layer, as legacy's did, since the inner panel hides at once.

Verified: in `../ui`, `pnpm lint`, `pnpm types`, `pnpm build:pkg` and `pnpm build:storybook` green (the Storybook build's `"use client"` directive warnings 1074 against the baseline's 1008, the added modules of react-focus-on and motion, the same class the baseline carries).
