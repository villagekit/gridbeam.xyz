## The inventory (2026-08-03)

**Metadata boilerplate (the big one):**
- `SITE_URL` defined twice (`app/robots.ts:3`, `app/sitemap.ts:6`) + hardcoded `https://gridbeam.xyz/...` in `app/layout.tsx:29,41` and `openGraph.url` in ~14 page files. With `metadataBase` set in the root layout, `openGraph.url` accepts relative paths.
- Every page repeats `openGraph`/`twitter` `{title, description}` blocks that Next derives automatically from `metadata.title`/`description` when omitted.
- Fix: one `SITE_URL` const in `app/_lib/`; per-page metadata shrinks to `title`, `description`, and (only if wanted) a relative `openGraph.url`. ~100 lines deleted.
- `app/twitter-image.tsx` just re-exports `opengraph-image` — delete (Twitter falls back to `og:image`; `twitter.card` is already set in layout).
- `app/layout.tsx:49-52` `robots: { index: true, follow: true }` is the default — delete.

**Config drift:**
- `biome.json:2` pins `$schema` 1.3.3; installed Biome is 1.9.4. `package.json:18-19` use `--apply`/`--apply-unsafe` (deprecated 1.8, removed in Biome 2). Fix: schema → installed version, scripts → `--write` / `--write --unsafe`.
- `tsconfig.json:16-17` — `forceConsistentCasingInFileNames` (default since TS 5.0) and `useDefineForClassFields` (default at ES2022 target) are redundant; delete.
- `smol-toml` in `dependencies` but only used by build-time `scripts/generate-designs-data.mjs` — move to `devDependencies`.
- `@chakra-ui/react` top-level dep is never imported directly (arrives via `@villagekit/ui`). Keeping it for version-dedup across transpiled packages is defensible — but make it a stated choice (comment in package.json is impossible; add a line to CLAUDE.md's repo-shape notes) or remove it and verify the build.
- Toolchain drift: `.nvmrc` 24.15 vs `engines >=22` vs pnpm pin — align intent (ask Mikey which Node line is canonical if unclear).
- Env docs: `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` (`app/_lib/cloudinary.ts:11`) and deploy-critical `NEXT_PUBLIC_DEPLOY_ENV` (`app/robots.ts:12`) are read by code but absent from `.env.example` and `wrangler.jsonc`; the robots.ts comment references a wrangler `vars` entry that doesn't exist. Document both; consider the actual `vars` entry.

**Scripts:**
- `scripts/rebuild-audit-index.mjs:68-127` duplicates ~70 lines of `renderIndexHtml` + CSS from `scripts/audit-pages.mjs:121-189` — fold into a `--rebuild-index` flag or shared module.
- `scripts/screenshot.sh` is a third screenshot path beside the Playwright tooling — delete if superseded (check nothing references it).
- Generated-data posture: `app/_lib/designs-data.generated.ts` is both committed AND regenerated by `predev`/`prebuild` every run. Keep committed (typecheck-without-generate) and either make the hook a staleness check or document the belt-and-braces in the script header.

Preferred: make `generate-designs-data.mjs` emit the image-import module too (it already enumerates ids and the `<id>/<id>.png` convention); minimum: generator warns/fails on missing image entries.
